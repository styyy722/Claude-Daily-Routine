# Claude Daily Finance Routine Instructions

This repository stores automated daily financial news reports generated by Claude Routine.

## Main task

Each routine run must generate **two** new markdown reports — one in English and one in Chinese (Simplified) — for the **previous calendar day** using Australia/Sydney time (AEST/AEDT), and must also **backfill any missing reports from the prior 14 days**.

**Date calculation (do this first):**
1. Get today's date in Australia/Sydney timezone.
2. Subtract one day — that is the **primary target date** for this run.
3. Build the **backfill window**: the primary target date plus the 13 days before it (14 calendar days total).
4. For every date in the backfill window, the target filenames are:
   - English: `outputs/daily-finance/YYYY-MM-DD-financial-news-report.md`
   - Chinese: `outputs/daily-finance/YYYY-MM-DD-financial-news-report-zh.md`
5. For each file, check whether it already exists:
   - If it does **not** exist: generate and save it (see Report rules below).
   - If it **already exists**: skip it and move on.

This backfill step exists because runs can be missed (machine/network/tool outages) or can fail partway through. Scanning back 14 days lets the next successful run self-heal recent gaps instead of leaving them permanently missing. Do not go back further than 14 days, and do not re-use or re-send a report from any date outside the current backfill window.

Process dates **oldest first** within the window, and within each date, generate and commit English before Chinese — this bounds the damage from a mid-run failure to at most one file.

## Saving and committing to GitHub

Commit and push **each file individually, immediately after it is generated** — do not batch multiple files or multiple dates into one commit. This ensures that if the run fails partway through (e.g. after generating English but before Chinese, or after date A but before date B), everything generated so far is already safely committed and won't be lost or orphaned as an uncommitted file.

For each newly generated file:

```
git add outputs/daily-finance/YYYY-MM-DD-financial-news-report.md
git commit -m "Add English daily financial news report for YYYY-MM-DD"
git push origin main
```

(substitute the Chinese filename and an analogous message for the Chinese report)

- Only ever add the one file you just generated — never `git add -A` or `git add .`.
- If a file already existed, skip generating and committing it — do not touch it.
- If every file in the backfill window already exists, skip straight to the run log step below (no commit needed for reports).

## Report rules

- English report: use the template in `templates/daily-financial-report-template.md`.
- Chinese report: use the template in `templates/daily-financial-report-template-zh.md`.
- Keep each report around one page.
- The Chinese report is a full translation and localisation of the English report — same data, same structure, written naturally in Simplified Chinese.
- Include source links where available.
- Do not invent market data.
- Clearly state when data is unavailable.
- Do not provide personalised financial advice.
- Save only the final report files.

## Table formatting

The Market Snapshot table **must** be formatted as a code block (wrapped in triple backticks) with columns aligned using spaces — not as a markdown pipe table. This ensures the table renders correctly in Discord. See the templates for the exact format.

## Suggested public sources

Use reliable public sources to research each target date's market activity:
- Reuters business and markets coverage
- Yahoo Finance / market data pages
- MarketWatch
- CNBC Markets
- Federal Reserve official releases
- Reserve Bank of Australia releases
- ASX market information
- Commodity market pages for gold, oil, and iron ore

Prioritise market-moving information over general news.

## Discord delivery

After a report file is generated and committed, send its full content to Discord immediately (per-file, same as the commit step — do not wait until the end of the run) using:

```
python3 scripts/send_discord.py outputs/daily-finance/YYYY-MM-DD-financial-news-report.md
```

(or the `-zh.md` file for the Chinese report)

This script reads `DISCORD_BOT_TOKEN` and `DISCORD_CHANNEL_ID` from the environment, sets the required custom `User-Agent` header (Discord's Cloudflare edge blocks default `urllib`/`curl`/`requests` user agents with a 403), and automatically splits the report into sequential messages at section boundaries to respect Discord's 2000-character limit. Do not post to Discord manually with raw `curl` — always use this script so the User-Agent fix is applied consistently.

If the script fails (non-zero exit code), note the failure in the run log below but continue processing the remaining dates/files — do not abort the whole run over a single Discord delivery failure.

Within a date, send English to Discord before Chinese, matching generation order.

Do not include any Discord token or secret in this repository.

## Run logging

At the very end of every run — whether or not anything was generated — append one line to `outputs/daily-finance/run-log.csv` recording what happened, then commit and push just that file:

```
git add outputs/daily-finance/run-log.csv
git commit -m "Log routine run for YYYY-MM-DD"
git push origin main
```

CSV columns: `run_timestamp_utc,primary_target_date,dates_generated,dates_already_present,discord_failures,notes`

- `run_timestamp_utc`: current UTC time when the run executes, e.g. `2026-08-29T21:03:11Z`.
- `primary_target_date`: the single YYYY-MM-DD computed in step 2 of Main task.
- `dates_generated`: `;`-separated list of YYYY-MM-DD dates for which at least one file was newly generated this run (empty if none).
- `dates_already_present`: `;`-separated list of YYYY-MM-DD dates in the backfill window that needed no action.
- `discord_failures`: `;`-separated list of `YYYY-MM-DD:en` or `YYYY-MM-DD:zh` entries for any Discord send that failed (empty if none).
- `notes`: free text for anything else worth recording (e.g. a research source that was unavailable).

This log is the only record of whether the routine actually fired on a given day — keep it append-only, never edit past rows.

Create the file with a header row if it does not already exist:
```
run_timestamp_utc,primary_target_date,dates_generated,dates_already_present,discord_failures,notes
```
